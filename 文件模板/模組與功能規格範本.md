內容主源指文件／章節；維護者及 Decision authority 指人及其責任。共同 baseline、來源及確認依據可繼承引用，不重寫摘要或 receipt；本文件自身的 scope／內容主源及局部差異仍須明示。未決只在相關正文或本欄記一次影響、責任人、下一步及解除條件，其他位置引用；缺少來源明示待建立／未確認，不以空白引用代替資訊。

小模組可以合併模型及少量功能；只有內容或維護責任需要時才拆文件。沿用適用確認事件，不逐條 AC 重新批准。

## 1. 模組責任與概念（適用時）

- 模組邊界：待填；說明此業務概念／規則由何處起、至何處止。
- 提供的業務結果／能力：待填
- 不擁有的相關行為及其 normative owner：待填
- 主要 user groups／actors：待填（引用產品骨架的 ID／章節）
- Stakeholder／決策 authority：待填或引用；只在與產品骨架不同時說明差異。
- 重要依賴、來源及適用政策：待填

模組是業務概念與規則責任，不等同角色端、頁面、API group 或技術 service。

- 共用資格、read／write 範圍、欄位可提供／修改者及條件（若跨功能）：待填；單一功能規則留在其操作契約

若欄位來源或可改性有歧義，只在本模組既有規則表或單一功能契約記錄業務含義、誰可提供／修改及適用條件；不要另建平行欄位表。技術端引用該業務規則，記錄 request/source 的處理及實際 native 欄位；缺少業務決定時回相應 owner。

## 3. 功能規格（只展開本文件負責的部分）

沿用產品骨架的 Feature ID／章節；同一 Feature 可由多個模組或流程各自承接不同規則。本節只定義列明的局部語義與 AC，其他責任以有用途的 reference 連接，不在每個模組重建完整 Feature。小項目可合檔，每條原子規則／AC 仍只有一個正文主源。

## 6. 先自答、邊界與最低完成

此節是 review prompt，不是新增必填問卷：只補上文尚未回答且會改變下一步的資訊；已記載的值引用章節，不重複填。簡單 scope 可短答，無關處標 N/A 及理由。

- 這是 user goal、模組共用規則、單一功能操作，還是跨步流程？待填
- 共用 model／資格／狀態由哪個唯一 owner 定義；本功能新增了甚麼局部效果？待填
- 哪些 actors 是實際使用者，哪些是 stakeholder／批准責任？待填
- 每個重要成功、拒絕與失敗分支有可觀察結果嗎？待填
- 什麼是正式產品語義，什麼是技術表示、測試方法或本次結果？待填
- 哪個未知會阻塞本 scope；哪些工作可在既有授權下繼續？待填

**邊界：** 本文件擁有明列的模組／功能規則與 AC。來源處置與確認事件引用產品骨架／唯一決策事件；功能進度引用 primary tracker；技術 schema、部署及具體操作回技術設計 owner／Runbook；實際驗證回驗證紀錄；交付結果回交付紀錄。不要按角色端或 UI 另造同一業務 entity，也不把 test pass 當成需求確認。

**最低完成條件：** scope、normative owner、適用確認 reference 或「未確認」、actor／目的、資格／依據、成功與必要拒絕／失敗結果、相關共用規則 owner、足以判定的 AC、重要未決與責任人均已列出；條件式內容有理由標 N/A。非本功能細節只引用 owner，不複製平行規則。
