## 1. Source → artifact → target chain

| 交付環節 | 精確 identity／revision／hash | Owner／位置或 target | Scope／config |

| Source revision | 待填；含相關未提交／未追蹤輸入時引用[來源身份規則](../項目文件/00-協作與執行/規則與標準/工作規則與標準.md#evidence-綁定與回寫)要求的同一來源快照／差異 | 待填 | 待填 |

Source build、package、transfer、deployment 各階段獨立記錄。輸出檔名或 package Done 不單獨證明 source 已 build、artifact 新鮮或 target 已更新。

有多個產物、來源或 target 時，在本表按具名交付物分條目，讓第 2 節各階段能引用正確 identity。手冊／操作材料或多語交付只在有此承諾時展開 deliverable family／locale、canonical MD owner／revision、output artifact／hash，以及適用的截圖基線／review reference；可寫在相應條目或引用既有材料紀錄，不另建第二份 artifact 表。Publish／handoff 狀態只回第 2 節，同版號不代表不同語言已校準。

## 2. 各階段狀態與 receipt

每階段只在適用時填寫；不適用填 N/A 及理由，尚未執行填 NOT_RUN，受阻填 BLOCKED 及責任人。每列使用該階段自己的 source／artifact／environment 和 receipt。

| 階段／claim | 適用 scope／revision | State（待填／NOT_RUN／BLOCKED／實際狀態） | Observable evidence／receipt | Owner／時間 | 未證事項／下一步 |
| --- | --- | --- | --- | --- | --- |
| Build／package | 待填 | NOT_RUN | NOT_RUN | 待填 | 待填 |
| Transfer／handoff | 待填 | NOT_RUN | NOT_RUN | 待填 | 待填 |
| Deployment／target 更新 | 待填或 N/A（理由） | NOT_RUN | NOT_RUN | 待填 | 待填 |
| Runtime health／操作條件 | 待填或 N/A（理由） | NOT_RUN | NOT_RUN | 待填 | 待填 |
| User-visible 結果 | 待填或 N/A（理由） | NOT_RUN | NOT_RUN | 待填 | 待填 |
| User／client acceptance | 待填或 N/A（理由） | NOT_RUN | NOT_RUN；若未有有權角色的 receipt，保持未確認 | 待填 | 待填 |

各列 state 不互相推導。驗證結果引用驗證紀錄或 native run receipt；接受事件由具相應 authority 的 stakeholder 確認，並使用唯一 reference。CLIENT_ACCEPTANCE_PENDING、PRODUCTION_NOT_READY 或 POC_WITH_ASSUMPTIONS 等成熟度 claim 需附 scope、依據與阻塞條件。

部署前產物／前提檢查與部署後新 target 檢查各連到實際 run；後者須綁真正收到的 artifact、target 與時間，不能引用部署前舊版本的結果冒充。只 package／handoff 時，其餘階段按本次 scope 標 N/A；未驗階段保留未驗，不與不適用混淆。

若發生恢復／rollback，第 1 節補具名恢復後的 artifact／config／必要資料身份，本節追加相應恢復事件及驗證 reference；已有紀錄則引用。分清動作已執行與效果已驗證，保留原交付失敗及各自時間／scope，不以恢復成功覆寫原版本結果；效果未驗仍為 NOT_RUN／blocked。程序沿[版本交付的恢復分支](../項目文件/00-協作與執行/Runbooks/版本交付.md#failurestop-與-recovery)，不另建平行台帳。

## 3. Change、migration、recovery 與 handoff（條件式）

- 交付所含 change／相容性限制：待填
- 資料 migration／initial state／configuration change：待填或 N/A（理由）；操作方法回 Runbook，必要風險接受回決策 owner
- Backup／restore／rollback／recovery 前提與 owner：待填或 N/A（理由）；不在模板預設 destructive 操作
- 若本次 migration／restore／rollback 或 handoff 涉及刪除、覆寫或外部寫入，引用適用的工作任務授權、global／project `AGENTS.md`、[工作標準的破壞性操作規則](../項目文件/00-協作與執行/規則與標準/工作規則與標準.md#破壞性操作)及[版本交付 Runbook](../項目文件/00-協作與執行/Runbooks/版本交付.md)；通過兩道 gate 並於操作前重核 resolved exact targets。技術理由不自帶授權；仍適用的明確授權不重問。
- 接手方、使用／支援責任及 handoff 條件：待填或 N/A（理由）
- 未完成／不適用階段、已知問題、風險及補救責任：待填
- 本次交付已核對的 current normative owner／binding／native artifact：待填

## 4. 先自答、邊界與最低完成

此節是 review prompt，不是新增必填問卷：只補上文尚未回答且會改變下一步的資訊；已記載的值引用章節，不重複填。簡單交付可短答，無關處標 N/A 及理由。

- 這次實際承諾交付到哪一階段？每項 claim 有何 receipt？待填
- Source、artifact、config、target 與適用 scope 是否逐段綁定？待填
- 哪些階段未執行、阻塞、不適用或只完成部分？待填
- Runtime、user-visible 與 acceptance 是否各有足夠證據？待填
- 接手／rollback／support 的責任和條件是甚麼？待填或 N/A（理由）

**邊界：** 本交付紀錄擁有一次交付的 scope、各階段 state 與 receipt；source／artifact／target identity chain 在第 1 節維護，階段結果只在第 2 節記錄。Build/test 的本次結果引用驗證紀錄；部署操作回 Runbook；長期 runtime 契約回技術設計 owner；正式接受回唯一確認事件。一次交付紀錄不能改寫其他 target 的歷史、替代 current user manual 或把產品規則搬離其 normative owner。

**最低完成條件：** source revision、artifact identity、target／environment、各適用階段 state 與 receipt、未證範圍、接手／恢復前提、接受責任及限制均已明示；沒有證據的階段保留 NOT_RUN／BLOCKED／未確認，不標成完成。
