> 本模板描述一次可追蹤的工作 instance。建立前先選定平台或文件中的 primary tracker；已有 issue/task tracker 可用時引用它，不另做一份同步台賬。

入口：來源與內容 owner 見 [項目文件來源索引](../項目文件/README.md)；任務分類、授權與程序見 [00 工作入口](../項目文件/00-協作與執行/README.md)及[工作標準](../項目文件/00-協作與執行/規則與標準/工作規則與標準.md)。

Issue 可擁有問題、優先級及風險，implementation task 可擁有一次工作進度；兩者若不同，分別連結，不把其中一個狀態複製為另一個。Task Done 不自動 close Issue、令驗證紀錄通過、令交付紀錄部署或代表 user acceptance。

若工作或 claim 標為 BLOCKED，依[工作標準的結果／狀態規則](../項目文件/00-協作與執行/規則與標準/工作規則與標準.md#結果與狀態)分開記錄 blocker、run result、cause 與 owner；本 task 只擁有工作／依賴狀態，不由 BLOCKED 推定根因、PASS 或 non-defect。

## 1. 目標、current 與預期結果

- 要解決的問題／本次目標：待填
- Current／observed 狀態及證據身份：待填（已觀察／來源聲明／推論／假設）
- Intended 狀態／成功條件：待填；引用 normative owner，不在 task 重寫產品規則
- Scope 內的 repo、文件、功能、環境或 artifact：待填
- 明確 scope 外項目：待填；無則填「無」
- 哪些動作已授權；哪些需要別的決定／確認：待填
- 本次工作完成層：待填（調查／文件／source／驗證／交付／接受；可部分交接）

- Decision authority／風險接受責任：待填或引用權責來源；作者與 maintainer 不自動取得決策權

- 若 scope 涉及刪除／reset／overwrite／migration 或外部寫入，記錄既有授權 reference，並遵循適用 global／project `AGENTS.md`、[工作標準的破壞性操作規則](../項目文件/00-協作與執行/規則與標準/工作規則與標準.md#破壞性操作)及相關 Runbook；兩道 gate 適用時均須通過，並於執行前重新核對 resolved exact target list。技術需要不是授權；仍適用的既有明確授權不重問。
- 預計回寫的正式 owner／record：待填；局部規則有變才修改 owner，結果寫驗證／交付紀錄

**調查／修復交接（適用時）：** 在本任務或已有調查摘要中只補尚未有落點的資訊，已有內容用 reference，不新增台帳或每次重填一張表：

- 原問題與適用契約／失敗 evidence；目前原因假設、支持／反證及信心／未決分開。反證須說明推翻甚麼；只推翻原因假設不代表原問題已被否定，非缺陷判斷須有該 scope 的問題／契約證據。
- 下一個最小查證／修正及既有授權 scope；交接時連原失敗／基線、修正範圍與修後對應 check。實際觀察只留 VR／native run，根因判斷與行為回歸的 claim 分清。
- 有風險接受處置時引用有權事件、scope、責任及適用的期限／恢復條件；不因此改寫缺陷事實、驗收或執行結果。重要取捨才需要決策紀錄，已有事件直接引用。

## 4. 驗證、回寫與 closure

- 實際驗證使用的驗證紀錄 reference：NOT_RUN；run 尚未執行時保留此值與阻塞原因
- 實際交付使用的交付紀錄 reference：NOT_RUN；沒有交付 scope 時填「N/A」及理由
- 規範正文回寫／只核引用／派生索引更新：待填；未變更時寫原因
- 本次剩餘未完成、風險與明確 handoff：待填
- Task closure 條件：待填；僅在達到本次目標或清楚交接時結束本 instance
- Reopen／追加工作條件：待填

## 5. 邊界與最低完成

**邊界：** Task 擁有本次工作計劃與進度，不擁有長期產品規則、決策批准、run 證據或交付結果。每個 instance／狀態維度一個 primary tracker；不同維度可有不同 records。由新證據發現的規則改動須回 current normative owner，不能只寫在 task。

**最低完成條件：** 唯一 ID、primary tracker／狀態維度、目標與允許動作、scope／baseline、current normative references、影響與風險、前提／未知、完成／停止條件、實際驗證／交付紀錄 reference 或「NOT_RUN／N/A」理由、回寫與 handoff 均已填妥。所有 pending 欄位保留明確狀態。
