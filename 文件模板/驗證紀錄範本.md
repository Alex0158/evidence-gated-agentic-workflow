## 1. 證據身份與適用範圍

- 此紀錄證明的 claim：待填；只限本次 scope、revision、artifact 與 environment
- 證據層：待填（文件／static／source inspection／build／unit／integration／runtime／user-visible／acceptance 等）
- Evidence path：待填（claim → 適用入口／輸入 → 操作與分支 → 可觀察 assertion／receipt；指出省略邊界）
- 證據身份：待填（已觀察執行結果／source 聲明／generated mapping／推論／假設）
- 本次使用的 current spec／confirmation reference：待填；需求未確認時明示「未確認」，不以執行結果補成批准
- Source revision → artifact identity → target/environment → receipt 的對照：待填；不適用的段落說明理由
- 安全 fixture／test data 的來源、隔離範圍及是否為 synthetic：待填；不得貼入真實秘密或無必要個資
- 人工／工具或 source 核查（適用時）：記實際方法、範圍、輸入及觀察的證據位置；已有欄位承接就引用。主張「未找到」時記搜尋範圍、方法及限制；不把它外推至未查版本、其他環境或 runtime。

文件／static check、source、build、test 執行、runtime、部署、user-visible 與接受是不同證據層。每一層只支持它實際檢查的 claim；targeted pass 不外推成 full suite pass，synthetic PoC 不外推為 production／client acceptance。API-only evidence 只支持 API claim；缺少 UI 入口不能裁決 API authorization，API PASS 也不能代替 user-visible golden flow（反向亦然）。

## 4. 結論、未知與回寫

- 本次 run summary：引用／從第 2 節逐項結果歸納支持的 claim 及限制；尚未執行即保留未執行事實。有意省略依 SKIP 規則處理，不重填另一個總結果；混合結果不可被摘要改成全部通過
- Work／claim summary state（如需）：待填或 N/A；BLOCKED／PARTIAL 屬工作或 claim 維度，引用 primary task／summary，不寫成 run result
- 已證明與未證明的範圍：待填
- 本次 run 當時的失敗分類／原因假設與信心：需要保留時記當時判斷及依據，或引用當時調查；未明則寫「未知」，結果標籤不推定根因
- 目前根因判斷／責任／下一步：引用既有 Task／調查摘要的主來源；沒有持續調查需要可 N/A，不為填本欄另建 Task 或重填同一結論
- Work／claim blocker 與依賴 owner：待填或 N/A（理由）；BLOCKED 是狀態，不是 run result，也不推出 PASS 或 non-defect
- 若 gate 本身屬本次 current contract／交付承諾，gate 缺失或錯誤可列為 defect candidate；按[修復缺陷 Runbook](../項目文件/00-協作與執行/Runbooks/修復缺陷.md)核對 expected、scope 與 evidence 後再分類
- 需要修復／重新驗證的 current owner 或 task reference：待填或 N/A（理由）
- 舊 evidence 是否仍適用及判定依據：待填；新 branch／environment 不自動變成新的 pass
- 這次只核引用或是否需更新規範：待填及理由；穩定規則改變回 normative owner

當時原因假設後來被推翻，保留本 run 的原觀察與當時判斷，連到後續調查／更正；目前原因與處置由選定的 Task／調查摘要更新。不把歷史 VR 改成最新根因，也不要求兩處持續同步同一判斷。

若 command 會改動資料／外部系統或涉及 destructive action，引用仍適用的工作任務授權，並遵循適用 global／project `AGENTS.md` 的完整規則及[工作標準的破壞性操作規則](../項目文件/00-協作與執行/規則與標準/工作規則與標準.md#破壞性操作)、[驗證功能 Runbook](../項目文件/00-協作與執行/Runbooks/驗證功能.md)：通過 necessity 與 impact／recoverability 兩道 gate，執行前重新核對 resolved exact target list。技術需要本身不構成授權；已有且 scope 仍適用的明確授權不重問。Scope 不明或 fixture 不安全時停止依賴該操作的 claim。

## 5. 先自答、邊界與最低完成

此節是 review prompt，不是新增必填問卷：只補上文尚未回答且會改變下一步的資訊；已記載的值引用章節，不重複填。簡單 run 可短答，無關處標 N/A 及理由。

- 這次要證明哪條 claim／AC；它的唯一規格 owner 是哪個？待填
- Source、artifact、environment、fixture 與 command／操作是否有身份可核？待填
- Expected 與 observed 是否分開；哪些 forbidden effects 有被檢查？待填
- 本次證據層最高支持到哪裡；哪些範圍不可外推？待填
- 每個 NOT_RUN／FAIL／SKIP run result 是否有原因與影響；若工作／claim 為 BLOCKED／PARTIAL，是否連到其 primary owner？待填

**邊界：** 本紀錄擁有某次 run 的實際觀察；需求／AC owner 定義 expected；test asset 擁有執行的 assertion；coverage view 只彙整關係。不得因文件存在、static PASS、build 成功、health up 或某條 targeted pass 宣稱其他證據層完成。

**最低完成條件：** claim、scope、baseline、source／artifact／environment 身份、runner／操作、expected／observed、逐項結果及 evidence reference 可追溯；未執行時保持 NOT_RUN 並說明 blocker；結論清楚寫支持與不支持的範圍及回寫 owner。
