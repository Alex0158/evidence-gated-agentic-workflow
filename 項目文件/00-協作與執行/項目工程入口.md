# 項目工程入口

內容身份：工程設定與工具入口的導覽。未初始化時精確值來自 [project.json](../../.workflow/project.json) 通用模板；初始化完成後 `.workflow/instance.json` 是本項目的唯一 active binding，模板不再作 current 值來源。本文件不預填產品綁定或準備程度，也不手抄完整值表。

解析規則由 [native workflow_support.py](../../scripts/workflow_support.py) 承接：有 instance 時讀它，否則讀模板的 project.mode、repositories、commands、environments、data 及 framework 基線。TEMPLATE 表示未初始化；PROJECT 只表示項目草稿／身份已建立，**不表示需求已批准、產品已實作或生產就緒**。產品 readiness 依範圍／風險另判。

commands 的 entry 必須實際存在。argv 是呼叫形式，讀取 JSON 不構成執行授權；執行前核本次 scope、程式來源及環境。product_build/test/run 為 null 時明示沒有 runner／NOT_RUN，不猜命令。Framework checks 只查本地 artifact 與路由，不跑產品或連外部帳號。

## 框架版本與來源身份

`framework.version` 標示採用的底座版本；候選版仍是候選，不能由該值推定 GitHub tag 或 Release 已發布。公開採用時，以實際 repository URL、版本對應 tag 及其 commit 核對來源；本地候選則核其指定 branch／commit，不要求讀作者研究資料。

`framework.design_baseline` 與 `framework.source_sha256` 保留設計來源的歷史身份；後者是設計稿 digest，不是目前整個 repository、安裝內容或 release artifact 的 checksum，也不要求採用者取得該設計稿。初始化會沿用這些 framework 欄位到 active instance。後續採納範圍與證據回既有工作／交付紀錄，不重定義欄位或另造版本台帳。

## 文件檢查範圍

[Native check_docs.py](../../scripts/check_docs.py) 有兩條獨立維度；初始化不會自動擴大文件檢查範圍：

| 維度 | 判讀方式 |
| --- | --- |
| 初始化身份：TEMPLATE／PROJECT | TEMPLATE 容許宣告的三份生成草稿尚未存在，輸出以 `deferred_generated_paths` 列明；已存在的草稿仍會檢查。PROJECT 要求這些生成入口存在。兩者均不判定產品 readiness。 |
| 檢查範圍：default／`--project-docs` | Default 查框架必需 MD 與已存在的宣告生成文件之 local file links，不查 anchors，也不自動納入後續新增文件。`--project-docs` 在預設範圍外加入 `項目文件/**/*.md`，並對所選文件檢查本地章節 anchors。 |

新增／修改項目文件或章節引用時選用 `--project-docs`，並核輸出的 `project_docs_scope`、`anchors_checked`、deferred paths 與錯誤清單。它仍不是所有目錄／格式、Markdown renderer、外部 URLs、產品 AC／語義或 runtime 的驗證；anchors 使用工具自身的解析規則，不能代替實際呈現檢查。

命令項目顯示 `ENTRY_EXISTS_NOT_EXECUTED` 只表示宣告入口檔案存在，沒有執行 runner。Checker 不證明 argv 實際可執行、外部服務可用或所有 binding 欄位均正確；缺少產品 runner 仍為 NOT_RUN。PASS 只支持本次工具輸出所列靜態條件，需求確認及準備程度回適用來源判斷。

Checker 的 `on_demand_documents_created` 目前固定為 `false`；checker 本身不建立按需文件，這個欄位也不判定項目中是否已有此類文件。是否建立成功，核 `create_document.py` 的原始 receipt（如 `DRAFT_CREATED`）及實體文件；不因 checker 的這個值否定已發生的生成結果。

## 生成與工程前提

三個核心草稿入口採固定路徑，以 [native workflow_support.py](../../scripts/workflow_support.py) 的 `CORE_DOCUMENT_TARGETS` 為唯一固定契約；binding 的 `generated_documents.target` 是須匹配的宣告，不是可改名／搬位的設定。工具在寫入前拒絕不符的宣告，不自動搬移、覆寫或重建。內容成長時保留入口，將正文拆到適當 owner 後由入口連接；五類按需文件的目的地仍可在 active binding 的 `document_templates` 定義。舊項目採用本版前若已有自訂核心路徑，先保留原內容並安排相容採納，不強改成預設路徑。

初始化在本 clone 內進行，生成三份產品／模組／設計草稿並記 receipt；已有產品內容或初始化過的項目必須拒絕，沒有 force/reset/clean。其餘五種需用的記錄由 create_document.py 按唯一註冊 template／target directory 建立；工具先核名稱和 target，按目標位置重基準 links，且不覆寫既有檔案。框架精確命令在 binding JSON，操作與 failure 分支回 [啟動項目](Runbooks/啟動項目.md)；資料前提／runtime 拓撲在它們自己的 owner，單次使用狀態回工作／驗證紀錄。

Native config 自身可隨項目綁定已存在的 runner、相對 roots 和實驗資料；變更前核其 primary owner／原值／影響，保留來源基線。絕不保存 secrets 或將 fixture 身份當 production authentication。換機先核 Python／native source／資料根／framework revision，不把此機器的 absolute path 當通用規範。

工具要求 Python 3.11+；2026-10-21 本地整合驗證涵蓋 macOS 上的 Python 3.11.13 與 3.14.2，包含原工具測試及隔離 clone／生成／拒絕覆寫程序。這些是實測版本點，不外推全部 Python 版本、Linux／Windows 或 GitHub runner；候選的遠端驗證狀態見[採用入口](../../README.md#本地驗證github-ci-與限制)。執行前在實際使用的 shell 核 `python3 --version`；另一個 shell 的 PATH 及版本不能代替本次前提。

初始化不覆寫 base config，只在資料完整後以不覆寫語義發布 instance；staging candidate 為同 inode 的工作別名，不作 immutable 歷史證據且不要編輯。沒有硬連結支援便安全停止，保留 partial receipt、草稿與原始模板。初始化要求本 clone 的 exclusive maintenance，未宣稱對 hostile concurrent directory replacement 的完整防禦。

部分失敗不自動恢復／刪檔：讀 `.workflow/init-partial-*.json`、備份、已建立的路徑和 hash，確認 active binding 是否已發布；保留原資料，在新目的地從保留來源明確採納／重新生成，或由 owner 精準協調，不使用 force/reset/clean。
