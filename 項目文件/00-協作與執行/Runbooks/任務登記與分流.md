# Runbook：任務登記與分流

## Trigger 與邊界

在調查、開發、修復、SDD、TDD、驗證或交付中，發現需要稍後處理、他人接手、決策或追蹤的問題／工作時使用。目的是留下可接手的問題、責任與下一步；程序的 must-hold 由[工作規則與標準](../規則與標準/工作規則與標準.md#任務登記與處置)承接，欄位格式由[工作任務範本](../../../文件模板/工作任務範本.md)承接。

影響目標、安全／資料、核心業務或共用鏈路、超出原工作 scope 而需後續處理，或關鍵 evidence 可能遺失的重要發現，應在途中先做最小登記，不等根因、完整規格或調查結束。其餘搜尋細節、已有任務涵蓋的工作、已在本次完成的小事可更新原紀錄，不為每個情境、測試或想法新增 Task。

登記、優先級、排程、需求確認、實作授權及風險接受分開判定。本程序不修改產品契約、不授予修復／外部寫入／公開權，也不指定所有項目必須用同一平台、狀態 enum 或 P0／P1 門檻。

## 讀者與前提

發現者、問題／工作 owner、triage／排程決策者及接手者，先核對項目已指定的 primary tracker、既有 Issue／Task、[工作路由](../README.md)及[內容來源](../../README.md)。可用平台 Issue 或本地文件；同一 instance／狀態維度只有一個主源，已有 tracker 不另造同步台帳。Issue 與 implementation task 只有 scope／狀態責任確需分開時才分記並連結，簡單工作可共用一份 record。

只在已授權目的地建立／更新。外部 tracker 不可寫、目的地未明或本次唯讀時，交付去除敏感內容的自足 handoff／草稿與待登記目的地或待決事項，不宣稱已入 tracker。既有授權內可繼續的獨立工作照常推進，登記不會擴大查詢或實作 scope。

## 操作程序與判斷分支

1. **判斷後續工作處置**：對重要 finding 判斷是更新既有項、新增待處理項、本次已完成而回寫原紀錄，還是無後續處理需要而保留結論／理由與適用重開條件。不要求先有完整分析；重要發現先保存已知內容及未知，再在來源工作收尾補齊。
2. **查重並選主源**：先在已授權範圍作有界搜尋，核標題／別名、功能／模組、問題現象、契約／AC、baseline／環境、影響及來源 evidence；重要發現可按下方待查重分支先捕捉，不等待完整搜尋。
   - 可確認同一問題及 scope 已有記錄：追加本次來源／日期與新 evidence，沿用其 ID／主源；根因未知本身不阻止同案更新，不複製一份狀態。
   - 僅症狀相似、尚不能確認同一問題及 scope：先標 related／疑似重複及理由，不僅因名稱相近而合併、關閉或刪除。需分開原因、工作或狀態時保留關聯。
   - 舊項已結束但本次再發生：按下方[關閉與重開](#跟進關閉與重開)核同一 scope 的重開條件；範圍實質不同時建立關聯新項，不覆寫舊結論。
   - 查詢不足或 tracker 不可讀：標明查重範圍、限制及後續查重行動。重要發現可先在允許位置保存為待查重／待登記；若只是指定 primary tracker 以外的暫存，明示其身份，不以暫存定位宣稱已入主源，也不臆造平台 ID。
   - 取得正式主源後：將暫存中的獨有 evidence 安全連入或引用到該主源並 readback，再把暫存項標明已對帳、指向主源；同一狀態維度只續寫主源，暫存不再維護第二份狀態。未完成核對仍記待對帳；原捕捉及其來源保留，不以對帳為由刪除或搬移。
3. **最小登記**：依[範本首次最小登記](../../../文件模板/工作任務範本.md#首次最小登記與補齊時點)保留唯一定位、問題／來源與證據身份、已知影響、暫定分類／狀態、下一責任及最小行動／Route。初次欄位可明寫 unknown／待評估／待指派，並留下誰或哪個既有 owner 需要作下一個判斷；連責任來源也未知時，先記缺口及責任確認行動，不阻止捕捉。不要為填滿範本編造根因、規格、排程或批准。
4. **分類並保持證據身份**：區分待調查／unknown、candidate defect、doc drift、需求／規則變更 proposal、改善建議、環境／fixture／工具 gate、待決或其他項目適用類型。分類先為 Route 服務，可隨新 evidence 修訂；觀察、推論、原因假設及已確認契約分開。沒有正式 expected 或充分 evidence 時，不把候選問題寫成已證 defect；分析中的建議也不寫成已採納需求。
5. **安排優先級與責任**：
   - 先記問題影響／嚴重程度，再按項目既有政策提出處理順序：考慮業務結果、影響範圍／頻率、安全／資料／相容風險、時效、可恢復性、依賴及處理成本，說明 evidence、信心及未知；不只因容易修或程式碼少而提高優先級。無既有等級時可文字描述，不能假裝已有全局分級規則。
   - Priority 建議、已裁決優先級與已接受排程分開；優先級的唯一 owner 在 Issue／指定 tracker，其他 Task 引用它。未知不阻止捕捉，但需列下一個評估行動；高風險的「延後」仍需適用風險決策，不默認風險已被接受。
   - 區分下一動作責任人、產品／風險決策者與實作者。可提出建議責任人；未確認承接時記待指派／待交接，以及原要求者或已知 owner 的下一個責任確認行動，不把填入姓名當成承諾。對外通知或轉交仍需相應授權與可回查結果。
6. **Route 並補足下一步前提**：分類、範圍及允許動作足夠後，依下表分流；尚無後續執行權時保留待處理與具體決策點。既有授權成立就繼續，不因登記多造批准。按下一步實際需要補範本的 scope、依據、依賴、完成／停止與驗證條件；調查任務不用先具備實作規格或修復權。

| 下一步要完成甚麼 | Route 與邊界 |
| --- | --- |
| 查清事實、原因、來源衝突或 gate | [調查與分析](調查與分析.md)；候選分類可保持未知。 |
| 核對／補足／確認需求或契約 | [規格驅動開發](規格驅動開發.md)；proposal 可作成果，未確認不改 current。 |
| 建立項目方向或重大重定向 | [啟動項目](啟動項目.md)；單一 feature 不重開全局 brainstorm。 |
| 修正相對正式預期的偏差 | [修復缺陷](修復缺陷.md)；須有適用 evidence、正式預期及修復授權。 |
| 實作已確認且已授權的功能／技術變更 | [開發與變更](開發與變更.md)；由主流程按條件呼叫 SDD／TDD，不為每個小步另建待辦。 |
| 證明已定義 claim | [驗證功能](驗證功能.md)；verify-only 不擴成修復。 |
| Build、交接、部署或發布 | [版本交付](版本交付.md)；各階段仍需有效授權及 gate。 |

分流後返回來源工作繼續已授權且獨立的部分，或由具名後續工作沿選定 Runbook 推進。有實際主源 readback 才報已登記，有可回查承接結果才報已交接；只有草稿時明示待登記／待交接。

## 跟進、關閉與重開

更新新 evidence、分類／優先級理由、依賴、責任及下一步，保留原 scope／baseline 與修訂依據；實際 run 引原 VR／native result，不複製整份分析、規格或 logs。

| 處置 | 條件及需保留的內容 |
| --- | --- |
| 完成本 instance | 本次目標與完成層所需 evidence 已具備，且符合項目 closure 權責。調查完成、實作完成、驗證、部署及 acceptance 各自判定；Task Done 不自動 close Issue。 |
| 交接／轉交 | 記剩餘 scope、接手主源／責任、必要 evidence、依賴及承接結果。調查目標完成且成果可回查時，可完成調查 instance，後續尚未承接仍記待交接；目標本為完成交接時，另需可回查承接結果。未完成實作仍記待續／轉交，不以 handoff 文字當成修復、承接或排程完成。 |
| 延後／拒絕／風險接受 | 依項目有權處置記理由、scope、責任及適用的重議時點／條件。尚未裁決仍為建議／待決；延後不取消缺陷事實、required checks 或必要風險接受。 |
| 重複項 | 記 duplicate 判斷依據、保留的 primary record 及獨有 evidence 去向，再按項目權責處置；不刪原證據或為整理而合併／搬移歷史。 |
| 重開或追加關聯項 | 問題持續／復發、原因假設被否定、新 evidence 擴大影響、確認／風險接受條件失效，或完成 evidence 不再適用時，核對原 scope／baseline。相同問題可重開原項並記新觀察；實質不同範圍另建關聯項。舊 closure 與當時 evidence 保留。 |

未重現、unknown、BLOCKED 或局部 PASS 均不單獨證明問題已修復。採納新規格時仍保留原失敗及處置依據，不能靠改驗收抹去原 Issue。保留安全且獨立的已授權工作，避免一個待決項全面擋住其他工作。

## Failure、驗證與 Exit

建立／更新後讀回實際 tracker 或本地檔案，核對 ID／定位、主源、內容、狀態、下一責任與 Route；只有文字已生成不代表已登記、版本化或承接。寫入 timeout／結果不明時依[外部未知結果規則](../規則與標準/工作規則與標準.md#外部操作授權時點與未知結果)對帳，不盲目重建重複項。目的地／權限／privacy 前提不成立時交安全 handoff；只有確認未派送或結果確為未寫入時才報未寫入。已派送而未能對帳時，保留 outcome unknown、原操作 reference 及下一查證責任，不因其後權限失效或無法 readback 改判未寫入，也不宣稱已登記。

Exit 留下已更新／新登記項的實際 reference、無需新增的理由、仍待登記／待決／延後部分及下一步；不要求另建總台帳。長期規則回原內容 owner，本次處置回原 tracker／dated record，工作分類與產品規格保持各自責任。
