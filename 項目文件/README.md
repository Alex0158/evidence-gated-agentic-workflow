# 項目文件來源目錄

本檔是內容 source map：它說明不同問題由哪類正式來源負責、何時閱讀及哪些內容不由它承接。工作分類與程序選擇由[00 工作路由](00-協作與執行/README.md)負責；本檔不複製 Runbook。文件只在內容需要與維護責任成立時建立，不按完整 Tree 預造空檔。

## 初始化生成的草稿入口

初始化器建立以下三個固定相對路徑作為可編輯的 draft 入口。正文可按 owner 拆分，入口保留並轉指詳細內容；固定契約及不符宣告的處理見[項目工程入口](00-協作與執行/項目工程入口.md#生成與工程前提)：

- [01-產品需求/產品骨架.md](01-產品需求/產品骨架.md)：合併承接全局產品骨架，以及來源／確認和主要情境的格式責任。
- [02-業務規格/業務模組/規格草稿.md](02-業務規格/業務模組/規格草稿.md)：近期業務模組與操作規格的起點。
- [03-系統設計/系統設計草稿.md](03-系統設計/系統設計草稿.md)：技術設計與契約的起點。

這些檔案由初始化生成不代表其中已有已確認產品值、schema/native source 或 acceptance。每個檔案依其內容補上 owner、scope、baseline、確認身份及依賴；細節與維護責任成立後再按需拆分。必要的 00 入口、模板與工作工具各有自己的 owner；不預造完整文件樹。未生成或不存在的 source 明示待建立或 N/A，不用文字描述取代實際可達的 link。

未初始化時以上三個入口明示為待生成草稿。檢查哪些文件、是否檢查章節引用及如何判讀結果，統一見[工程入口的文件檢查範圍](00-協作與執行/項目工程入口.md#文件檢查範圍)；初始化或文件檢查通過均不代表產品內容已確認。

## 內容身份

- **Current contract**：目前適用且可回查其 scope、baseline 和確認依據的正式要求。
- **Draft／proposal**：待討論或待確認內容；可供分析，不得當成已生效產品契約。
- **Historical input／record**：保留當時原始來源、決策或觀察；較新日期本身不提升權威。
- **Template**：只有格式及提示，沒有產品值或批准結果。
- **Generated／derived view**：從正式 owner 產生或核對的導航／覆蓋呈現，不另定規則。
- **Dated evidence**：綁定一次工作、source／artifact、環境及實際觀察；不代表後續版本或其他環境。

draft、current、superseded 描述文件內容生命週期，不等於 accepted、implemented、deployed 或 user accepted。若要表示確認，連到唯一的確認事件與它涵蓋的 scope／revision；如無法追溯，明寫 unknown／pending。

## 單一來源與最小回寫

一個原子語義在相同 scope／baseline 只有一個主要 owner。其他文件可作定位摘要、合法本地委派、實作／assertion 或日期化 evidence；它們必須保留各自身份，不能再自由定義另一套規則。

變更先改 primary owner，再沿正向關係核對真正受影響的 consumers、tests 和必要 derived view。只在含義、適用條件或入口變動時同步摘要；不要求全庫回寫、所有 backlinks 必讀或對每個小改動建一套 DEC／TASK／REL。

當技術欄位由 MD 交給 schema、types、API definition 或其他 native source 時，在技術 owner 記明新 owner、artifact／欄位 scope、baseline、差異處置與確認依據。先確認新 owner 可達且承接了必要語義和相容性，再把 MD 完整技術表改為有用途的入口引用；不要刪除歷史材料，也不要讓 MD 和 native source 長期並列為兩份可獨立修改的精確表。
